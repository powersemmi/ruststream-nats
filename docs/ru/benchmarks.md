# Бенчмарки {#benchmarks}

Фреймворк между клиентом NATS и обработчиком стоит времени на каждом сообщении: поток подписки,
декодирование, диспетчеризация, ack. Эта страница говорит, сколько именно. Точкой отсчёта служит та
же работа, написанная руками на `async-nats`.

Один процесс выполняет сценарий дважды: сначала как сервис RustStream, затем как цикл на клиенте.
Всё остальное держится одинаковым: параметры соединения, подписка, конфигурация консьюмера, место
подтверждения, декодирование в тот же тип, байты тела, рантайм tokio и сборка. Процедура
принадлежит самому фреймворку и описана на
[странице бенчмарков RustStream](https://powersemmi.github.io/ruststream/latest/ru/benchmarks/#methodology);
здесь опубликовано то, что она дала на этой машине.

## Числа {#the-numbers}

Медианы по одиннадцати чередующимся парам, в скобках наблюдавшийся разброс. Больше значит лучше.

| Сценарий | Сырой клиент | RustStream | Накладные расходы |
| --- | --- | --- | --- |
| Core NATS, 512 Б JSON | 1 635 001 сообщ/с (1 552 427-1 647 750) | 1 501 334 сообщ/с (1 490 862-1 529 421) | 8,2% |
| Консьюмер JetStream pull, 512 Б JSON, ack на каждое | 234 287 сообщ/с (232 869-236 999) | 236 224 сообщ/с (234 639-237 928) | неразличимо |

Строка Core NATS - это собственная стоимость фреймворка и ничего кроме неё: доставка там состоит из
совпадения субъекта и тела, и сервер ничего не подтверждает. Сырая доставка стоит на этой машине 612
наносекунд, доставка через RustStream - 666. Поток подписки, декодирование и диспетчеризация
добавляют к сообщению около 55 наносекунд.

Строка JetStream отмечена как неразличимая: разница между половинами меньше разброса между
прогонами каждой из них. Каждая доставка там несёт подтверждение обратно на сервер, и при
семикратной стоимости доставки Core разница такого размера в ней теряется. Число ниже шума прогонов
читалось бы как точность, которой никто не измерял, поэтому оно не публикуется.

Машинная форма того же прогона, из которой сайт фреймворка строит сводную таблицу по брокерам,
лежит по адресу
[`benchmarks/results.json`](https://powersemmi.github.io/ruststream-nats/latest/benchmarks/results.json).

## Машина {#the-machine}

| | |
| --- | --- |
| Процессор | AMD Ryzen 9 7900X, 12 физических ядер, 24 логических |
| Память | 62,4 ГиБ |
| ОС | Linux 7.2.6 |
| Брокер | `nats:2-alpine` в Docker на localhost |
| Rust | 1.98.1, профиль bench, без `RUSTFLAGS` |
| Версии | `ruststream-nats` 0.7.0 на `ruststream` 0.7.0-rc.7 |

Флаги сборки публикуются вместе с числами, потому что они эти числа меняют. Бинарник, собранный с
`-C target-cpu=native`, даёт результат, который не воспроизвести на другой машине, поэтому рецепт
очищает переменную перед сборкой.

## Чего эти числа не значат {#what-they-do-not-mean}

Это один консьюмер, один субъект, маленькое тело и сервер на локальной петле. Измеряется то, во что
доставка обходится внутри этого крейта, а не то, сколько способен пронести NATS. Строку отсюда
нельзя сравнивать со строкой, опубликованной для другого брокера: транспорты выполняют на сообщение
разную работу.

Окно прогона открывается на первой доставке и закрывается, когда возвращается последний обработчик,
одинаково у обеих половин. Фреймворк подтверждает доставку после того, как обработчик закончил, а
эту точку сам обработчик увидеть не может. Одно подтверждение из полутора миллионов остаётся за
пределами числа с обеих сторон.

Число JetStream снято на стриме в памяти с политикой work-queue. Так диск под сервером не попадает в
измерение, которое посвящено диспетчеризации. Стрим на файловом хранилище отвечает на другой вопрос
и отвечает про сервер, а не про этот крейт.

Числа - снимок одной машины в один день. Их переснимают по требованию и никогда в CI: шум общего
раннера больше разницы, о которой говорит эта страница.

## Как повторить {#running-it-yourself}

```bash
just bench
```

Рецепт поднимает стенд из `docker-compose.test.yml`, прогоняет оба сценария, гасит стенд и
переписывает `docs/benchmarks/results.json` тем, что намерил. Это занимает около десяти минут и
требует машину целиком. Число сообщений не фиксировано: пробный прогон подбирает его так, чтобы
каждый измеряемый прогон длился не меньше пяти секунд на той машине, где его снимают.
