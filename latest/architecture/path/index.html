    Path

    The way of one NATS message through a RustStream service: the subscription, the delivery, the handler, the reply and the settlement, on Core and on JetStream.

    A Core message is pushed by the server into the subscription. A JetStream message arrives in answer to a pull request, which async-nats sends for 200 messages at a time. Either way the NatsMessage keeps the client's message as it came, payload included.

    The headers are converted to the framework's map once, when the delivery is made. A message without headers builds no map at all. On Core, a request's reply subject is added as the reply-to header. On JetStream, the metadata is read from the acknowledgement subject when a handler asks for it, and not before.

    The handler's reply is encoded into a buffer, and the publisher hands that buffer over to async-nats as it is, without a copy. A Core publish returns once the client has taken the message. A JetStream publish returns once the stream has acknowledged it.

    The delivery settles after the reply. A JetStream acknowledgement is one message to the acknowledgement subject, sent without waiting for an answer. A Core delivery has nothing to settle: the call reports AckError::Unsupported and the runtime logs it. What each outcome does is on Settlement.

    The benchmarks count this path: the instructions and allocations of one JetStream delivery, the client's work on the service's thread included.
