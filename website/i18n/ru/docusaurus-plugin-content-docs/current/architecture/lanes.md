# Партиции воркеров

Подписка выдаёт сообщения по одному, а `workers(n, by_key)` раскладывает их по партициям воркеров
по ключу из заголовка `nats-partition-key`.

<Diagram name="lanes" words={words} />

Без `workers` один цикл вызывает обработчик для каждого сообщения по очереди. Порядок подписки
сохраняется, и ничего не выполняется параллельно.

`workers(n, by_key)` запускает `n` партиций воркеров. Сообщение попадает в ту партицию воркеров, на
которую указывает хеш его ключа, а партиция воркеров выполняет свои сообщения по порядку.
Собственных партиций у NATS нет, поэтому ключ - это заголовок
[`nats-partition-key`](../components/subscriptions/keys.md), который задаёт издатель. Сообщения
одного ключа сохраняют порядок, а разные ключи выполняются параллельно.

Между процессами работу делит сервер. [Очередь](../components/subscriptions/queue-groups.md)
отдаёт каждое сообщение Core одному участнику, в порядке, который выбирает сервер. Подписки,
привязанные к одному [durable-консьюмеру](../components/subscriptions/durable.md), берут сообщения
JetStream по очереди. [`max_ack_pending`](../components/subscriptions/max-ack-pending.md)
ограничивает, сколько сообщений консьюмера одновременно ждут ответа, по всем его участникам.

[Обработчик пакетов](../components/subscriptions/batches.md) берёт сообщения до размера, заданного в
точке монтирования. В JetStream один пакет - это одна выборка, которую досрочно закрывает
`pull_expires`. В Core пакет собирается на клиенте и закрывается по достижении размера или через 10
миллисекунд после первого сообщения.
