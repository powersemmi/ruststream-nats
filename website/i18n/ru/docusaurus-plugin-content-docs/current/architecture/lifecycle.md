# Жизненный цикл

[`NatsBroker::new`](../components/broker/index.md) записывает конфигурацию, connect
подключается к серверу, старт подписывается на каждый субъект или создаёт каждый консьюмер, а
завершение работы выполняет drain.

<Diagram name="lifecycle" words={words} />

`new` не выполняет ввода-вывода, поэтому билдер сервиса остаётся синхронным. Он принимает один
адрес или список адресов через запятую, а [`with_options`](../components/broker/connect-options.md)
задаёт параметры подключения `async-nats`. Рантайм подключает брокер при старте приложения.
Подключение использует эти параметры. Если сервер недоступен, старт прерывается с ошибкой
`NatsError::Connect`.

[Дескриптор](../components/subscriptions/index.md) каждой подписки разрешается один раз, по
подключённому брокеру. Подписка Core отправляет `SUB`, а затем ждёт ответа на flush. К этому
моменту сервер уже зарегистрировал подписку, поэтому издатель на другом соединении не может
опубликовать сообщение в промежуток. Подписка JetStream ищет свой стрим по имени и создаёт
pull-консьюмер, и на оба запроса отвечает сервер. Несуществующий стрим прерывает старт с ошибкой
`NatsError::JetStream`.

[Завершение работы](../components/broker/shutdown.md) сначала помечает соединение закрытым, чтобы
издатель, который на него ссылается, не успел отправить сообщение. Затем оно выполняет drain
клиента: подписки останавливаются, уже опубликованное отправляется, и соединение закрывается.
[`ClosedNatsBroker`](api:ruststream_nats::ClosedNatsBroker) хранит счётчики клиента: отправленные
сообщения, полученные сообщения и подключения.

Издатель, инстанцированный до завершения работы, - это дескриптор, который завершение не может
отозвать. Он возвращает ошибку `NatsError::Closed` с субъектом, в который его просили опубликовать.

Транспорт внутри процесса проходит ту же последовательность переходов жизненного цикла. Он
разбирает адреса так же, как connect, и читает `no_echo` и префикс инбокса из параметров
подключения.
