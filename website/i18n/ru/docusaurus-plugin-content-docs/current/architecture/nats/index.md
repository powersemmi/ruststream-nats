# Субъекты

Core NATS доставляет сообщение каждой подписке с подходящим субъектом, которая есть в момент его
прихода, и одному участнику очереди, а сам ничего не хранит.

<Diagram name="subjects" words={words} />

Субъект - это строка из токенов, разделённых точками. Субъект подписки может содержать шаблоны.
`*` заменяет ровно один токен. `>` заменяет один или несколько токенов и стоит последним.
Публикация всегда называет полный субъект, без шаблонов.

Сервер копирует сообщение в каждую подписку, которой оно подходит. Подписка, появившаяся позже,
его уже не увидит, а сообщение, которому не подошла ни одна подписка, пропадает. Это доставка
at-most-once: сервер ничего не хранит и ничего не подтверждает.

Очередь (queue group) делит работу между участниками. Сервер отдаёт каждое сообщение одному
участнику очереди, а подписка вне очереди всё равно получает свою копию. Очередь определяется
только именем, поэтому участники, подписанные на разные субъекты под одним именем, образуют одну
очередь.

Запрос - это публикация, которая называет субъект для ответа: инбокс, на который запрашивающая
сторона подписалась заранее. Отвечающая сторона публикует ответ туда. На запрос, которому не
подошла ни одна подписка, сервер сразу отвечает «no responders», поэтому запрашивающей стороне не
приходится ждать тайм-аута.

Начиная с NATS 2.2 сообщение может содержать заголовки. Имя заголовка состоит из печатных символов
ASCII без двоеточия, а значение - одна строка. Сервер отклоняет сообщение больше своего предела
полезной нагрузки, по умолчанию 1 МиБ.

Эта модель взята у самого сервера NATS
([субъекты](https://docs.nats.io/nats-concepts/subjects),
[публикация и подписка](https://docs.nats.io/nats-concepts/core-nats/pubsub),
[очереди](https://docs.nats.io/nats-concepts/core-nats/queue),
[запрос и ответ](https://docs.nats.io/nats-concepts/core-nats/reqreply)). Как стрим хранит
сообщения, показывает страница [Стримы](streams.md), а как консьюмер их читает, - страница
[Консьюмеры](consumers.md).
