# Путь

Путь одного сообщения NATS через сервис RustStream: подписка, доставка, обработчик, ответ и
завершение, в Core и в JetStream.

<Diagram name="path" words={words} />

Сообщение Core сервер сам отправляет в подписку. Сообщение JetStream приходит в ответ на
pull-запрос, который `async-nats` отправляет на 200 сообщений за раз. В обоих случаях
[`NatsMessage`](api:ruststream_nats::NatsMessage) хранит сообщение клиента в том виде, в каком оно
пришло, вместе с полезной нагрузкой.

Заголовки преобразуются в ассоциативный массив фреймворка один раз, при создании доставки. Для
сообщения без заголовков массив не создаётся вовсе. В Core субъект для ответа на запрос
добавляется в заголовок `reply-to`. В JetStream [метаданные](../components/context/index.md)
читаются из субъекта подтверждения, когда их запрашивает обработчик, и не раньше.

Ответ обработчика кодируется в буфер, и [издатель](../components/publishing/index.md) передаёт
этот буфер `async-nats` как есть, без копирования. Публикация в Core возвращает управление, как
только клиент принял сообщение. [Публикация в JetStream](../components/publishing/jetstream-publish/index.md)
возвращает управление, когда стрим её подтвердил.

Доставка завершается после ответа. Подтверждение JetStream - это одно сообщение в субъект
подтверждения, отправленное без ожидания ответа. Доставку Core завершать нечем: вызов возвращает
`AckError::Unsupported`, и рантайм записывает это в журнал. Что делает каждый исход, показывает
страница [Завершение](settlement.md).

[Бенчмарки](benchmarks/index.md#cost-of-the-code) считают этот путь: инструкции и выделения памяти
одной доставки JetStream, включая работу клиента на потоке сервиса.
