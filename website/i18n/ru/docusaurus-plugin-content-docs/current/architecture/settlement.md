# Завершение

Чем `ack`, `drop`, `retry` и [`retry_after`](../components/settlement/retry-after.md) становятся в
NATS: подтверждением, на которое действует сервер JetStream, и копиями, которые рантайм публикует в
Core.

<Diagram name="settlement" words={table} />

Доставка JetStream завершается на сервере. Ответ уходит в субъект подтверждения доставки, и
консьюмер поступает с ним так, как показывает страница [Консьюмеры](nats/consumers.md).
`retry_after` помещает задержку в само отрицательное подтверждение. Сервер придерживает сообщение
и повторно доставляет его тому же консьюмеру, с тем же номером в стриме и счётчиком `delivered` на
единицу больше. Ничего не публикуется, и копия не создаётся.

Доставку Core завершать нечем. `ack`, `retry` и `drop` возвращают `AckError::Unsupported`, и
рантайм записывает это в журнал. Сервер не хранит ничего для повторной доставки, и рантайм
возвращает сообщение только копией, которую публикует сам. Это доставка
[at-most-once](../components/settlement/at-most-once.md).

| Исход | Core NATS |
|---|---|
| `ack`, `drop` | `AckError::Unsupported` |
| `retry()` | `AckError::Unsupported`; при объявленном пределе копия публикуется сразу |
| `retry_after(d)` | копия публикуется через `d` |
| нет исхода | ничего |

## Повторы {/* #retries */}

<Diagram name="retries" words={retries} />

Предел объявляется в точке монтирования через
[`max_attempts`](api:ruststream::runtime::Mounting::max_attempts), и первая доставка считается
первой попыткой. В JetStream счёт ведёт сам сервер в своём `delivered`, поэтому доставка, которая
не уложилась в `ack_wait`, тоже учитывается. В Core рантайм считает опубликованные копии в
заголовке копии `x-ruststream-retry-count`.

Ниже предела каждая модель возвращает сообщение по-своему. JetStream повторно доставляет его из
стрима. В Core рантайм публикует копию по адресу, который сообщает дескриптор.
[`CoreSubject`](../components/subscriptions/core-subject.md) сообщает свой субъект.
[`CoreWildcard`](../components/subscriptions/core-wildcard.md) подходит ко многим субъектам и не
публикует ни в один из них, поэтому его регистрация [называет
субъект](../components/settlement/out-retry.md) для копии, иначе приложение не запустится.

На пределе доставка уходит в [субъект для недоставленных сообщений](../components/settlement/dead-letters.md)
в том виде, в каком пришла: полезная нагрузка и заголовки не меняются. Если субъект для
недоставленных не объявлен, доставка JetStream прекращается через `+TERM`, а доставку Core рантайм просто
отпускает.

Крейт ничего не объявляет серверу: `max_deliver` остаётся незаданным, потому что у JetStream нет
места, куда отправить сообщение, исчерпавшее доставки. Путь рантайма покрывает обе модели.
